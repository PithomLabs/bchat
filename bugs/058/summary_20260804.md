# The CockroachDB Deployment Story: Lessons from Bug 058

**Date:** August 4, 2026  
**Author:** opencode session  
**Scope:** CockroachDB Cloud Basic deployment to Fly.io, RAG pipeline debugging, build optimization

---

## The Problem Nobody Warned You About

Deploying a multi-tenant AI chat platform to CockroachDB sounds straightforward — until you discover that the database you chose for scalability is quietly sabotaging your migrations.

We deployed bchat to Fly.io with CockroachDB Cloud Basic (Serverless, v26.2.1). The health check passed. The machine came up. The app started. And then the RAG search returned zero results. Not an error — just silence. Five attempts, zero embeddings, no vector matches. The agent could talk, but it had nothing to say.

The root cause was insidious: CockroachDB Cloud Basic's DDL backfills are glacially slow — 25 to 60 minutes for large tables. During first boot, our migration ran all 57 `CREATE TABLE` and `CREATE UNIQUE INDEX IF NOT EXISTS` statements in a single window. The tables succeeded. The indexes did not. They timed out or were never reached. Because `IF NOT EXISTS` is idempotent, the application never errored. It just... operated without constraints.

When the reindex pipeline tried to save its progress, it hit `ON CONFLICT(tenant_id, audience, file_type, version)` with no matching unique constraint — `SQLSTATE 42P10`. The checkpoint couldn't be saved. The reindex failed silently. No embeddings were generated. The vector search returned empty because `resolveQueryVersion()` had nothing to resolve to.

Six missing indexes. One invisible failure. Hours of debugging.

## The Layers of the Problem

This wasn't a single bug — it was a stack of contributing factors, each masking the one beneath it.

**Layer 1: Stale vector DB state.** The machine from the previous session had a corrupted vector DB initialization. The `vectorDB` field was nil. A simple restart cleared it, but only because we knew to look.

**Layer 2: Missing unique indexes.** Even after the vector DB initialized correctly, search returned zero results. The reindex pipeline failed at the checkpoint save — the `ON CONFLICT` clause had no matching constraint. We had to manually create six indexes via `cockroach sql` against the live cluster.

**Layer 3: Silent failure mode.** The application's `IF NOT EXISTS` idempotency meant it never complained about missing indexes. It just skipped the operations that required them. This is a design trade-off: resilience at the cost of observability.

**Layer 4: No startup validation.** The vector DB initialization in `service.go` caught connection errors and fell back to `NoOpVectorDB` silently. There was no health check after initialization to confirm the database was actually functional.

## What We Fixed

The fixes were surgical, targeting each layer:

1. **Machine restart** — cleared stale vector DB state. This was a one-time operation, not a code fix.

2. **Created 6 missing unique indexes** directly on the live CockroachDB cluster:
   - `idx_reindex_checkpoint_tenant_audience` — for reindex progress tracking
   - `idx_rag_active_version_lookup` — for active version pointer
   - `idx_tickets_beads_id` — unique ticket constraint
   - `idx_tickets_creator_description_memo` — unique ticket constraint
   - `idx_bridge_handoffs_one_active` — one active handoff per session
   - `idx_agent_integrations_tenant_type` — unique tenant+type constraint

3. **Added `verifyCockroachIndexes()`** in `store/migrator.go` — a startup function that checks for missing indexes and creates them. This prevents the silent failure from recurring.

4. **Added vector DB startup health check** — after `NewVectorDB()` returns, we now call `Validate(ctx)` and log explicit errors instead of falling back silently.

5. **Fixed `crdb:verify`** — the verification harness unconditionally ran `TestCockroachP0`, a local-only destructive test, against production. It hung on a TLS read for 10 minutes and failed. We added a guard that skips the test against non-local DSNs.

6. **Fixed `validate-env-chain.sh`** — the env validation script hardcoded `fly.toml` and didn't account for CockroachDB-specific secrets. We parameterized it to accept the TOML filename and dynamically derive sensitive variables.

7. **Added production credentials** to Fly secrets and the project `.env` file, enabling the production smoke test.

8. **Promoted admin user to HOST role** in CockroachDB, granting super admin access needed for the onboard endpoint.

## The Docker Build Context Discovery

While optimizing the deploy pipeline, we stumbled onto a 1 GB Docker build context. The culprit: `lib/` — 518 MB of LanceDB CGO binaries — was included via a `!lib/` negation in `.dockerignore`. This was needed for LanceDB builds but unnecessary for CockroachDB (which uses pure Go with `-tags cockroach`).

The solution was elegant: `fly deploy` supports `--ignorefile`, so we created `.dockerignore.cockroach` that excludes `lib/`, `server/router/api/v1/agent/build/` (202 MB of build artifacts), `memos` (84 MB compiled binary), and `main` (84 MB compiled binary). The result: **1 GB → 643 KB** — a 99.94% reduction. Deploy time dropped proportionally.

The insight: `fly.toml` and `fly_cockroach.toml` already had separate Dockerfiles. The `.dockerignore` should have been separate too.

## The Lessons

### 1. Cloud Serverless DDL Is Not Like Local DDL

On a local CockroachDB instance, `CREATE UNIQUE INDEX` completes in milliseconds. On Cloud Basic, it can take 25 to 60 minutes. Your migration strategy must account for this. Options include: post-migration index verification, resumable DDL execution, or migrating to Cloud Standard for faster DDL.

### 2. `IF NOT EXISTS` Is a Double-Edged Sword

Idempotency prevents errors but hides failures. When a DDL statement silently succeeds as a no-op, you lose the signal that something went wrong. Consider adding startup verification that checks not just "does this table exist?" but "does this table have the constraints we expect?"

### 3. Verification Harnesses Must Match Their Target

`TestCockroachP0` was a local-only test that re-ran the entire migration. When `crdb:verify` ran it against production, it hung and failed. Tests must be aware of their environment. A simple DSN-based guard — skip non-local tests — prevents this class of bug.

### 4. Build Context Optimization Is Free Performance

A 1 GB build context means slower pushes, more network transfer, and longer deploys. The fix was trivial — a separate `.dockerignore` file and `--ignorefile`. The impact was dramatic. Always audit your build context size.

### 5. Silent Fallbacks Are Technical Debt

The vector DB initialization caught errors and returned `NoOpVectorDB`. This prevented crashes but hid misconfigurations. A health check after initialization — logging explicit errors instead of falling back silently — converts hidden debt into visible, fixable issues.

### 6. Separate TOML Files Need Separate Secrets Handling

`fly.toml` and `fly_cockroach.toml` use different databases, different DSNs, and different secrets. The env validation script hardcoded `fly.toml` and missed CockroachDB-specific variables. When you have per-backend configs, your tooling must be backend-aware.

## What Remains

The deployment is functional and verified. The smoke test passes all 7 steps. But there are items for the backlog:

- **Resumable DDL execution** — track which statements succeeded and retry failed ones on restart
- **Post-migration index verification** — query `SHOW INDEXES` after LATEST.sql and log warnings for missing constraints
- **4-phase LanceDB build enforcement** — compile-time tag guard, `CGO_ENABLED=0` pinning, automated purity verification, documentation
- **Commit pending changes** — 22 files modified across validation scripts, deploy tooling, and documentation

## Summary

### Root Cause
CockroachDB Cloud Basic DDL backfills take 25–60 minutes. During first boot, `CREATE UNIQUE INDEX IF NOT EXISTS` statements timed out silently. The application operated without constraints due to idempotent `IF NOT EXISTS` clauses, causing the RAG reindex pipeline to fail at `ON CONFLICT` upserts with no matching unique constraint.

### Fixes Applied
- Created 6 missing unique indexes on live cluster via `cockroach sql`
- Added `verifyCockroachIndexes()` startup verification in `store/migrator.go`
- Added vector DB `Validate()` health check after initialization
- Fixed `crdb:verify` — skip local-only `TestCockroachP0` against non-local DSNs
- Fixed `validate-env-chain.sh` — parameterized TOML, dynamic sensitive vars
- Added production credentials to Fly secrets and `.env`
- Promoted admin user to HOST role in CockroachDB
- Created `.dockerignore.cockroach` — reduced build context from 1 GB to 643 KB
- Updated `crdb-deploy.sh` with `--ignorefile .dockerignore.cockroach`

### Key Insight
Cloud Serverless DDL backfills are not comparable to local DDL. Migration strategies must account for 25–60 minute backfill windows. Idempotent DDL (`IF NOT EXISTS`) prevents errors but hides failures — startup verification is essential.
