## Root Cause Analysis

### Problem: RAG search returned "RAG pipeline not enabled" (HTTP 400)

**Layer 1 — Vector DB not initialized (resolved by restart)**

- `h.service.vectorDB == nil` at `handlers.go:6077`
- The machine from the previous session had a stale/corrupted vector DB state
- After restart, startup logs confirmed correct initialization:
  ```
  INFO Using CockroachDB native vector storage
  INFO CockroachDB vector store initialized with shared connection pool
  ```

**Layer 2 — Missing unique indexes (root cause of 0 results)**

- Even after vector DB initialized, RAG search returned 0 results
- The reindex pipeline failed silently because:
  1. `agent_reindex_checkpoints` table was missing `idx_reindex_checkpoint_tenant_audience`
  2. `ON CONFLICT(tenant_id, audience, file_type, version)` clause had no matching unique constraint
  3. Error: `SQLSTATE 42P10 — there is no unique or exclusion constraint matching the ON CONFLICT specification`
  4. Reindex checkpoint couldn't be saved → reindex failed → no embeddings generated
  5. Even when reindex succeeded (chunks inserted), the active version pointer couldn't be set
  6. `resolveQueryVersion()` at `service.go:5044` returned nil → search returned empty

**Why the indexes were missing:**

- LATEST.sql uses `CREATE UNIQUE INDEX IF NOT EXISTS` for all indexes
- During initial first-boot migration, these DDL statements were executed against CockroachDB Cloud Basic (Serverless)
- CRDB Cloud Serverless DDL backfills are extremely slow (25-60 min for large tables)
- The `CREATE TABLE` statements succeeded (tables exist with all columns)
- The `CREATE UNIQUE INDEX` statements either timed out or were never reached in the migration window
- Because `IF NOT EXISTS` is idempotent, the application didn't error on startup — it just silently operated without the constraints

## Future Prevention: What Needs To Be Done

### Problem: DDL backfill timeouts on CRDB Cloud Serverless

The core issue is that `LATEST.sql` runs all DDL (tables + indexes) in a single migration window, but CRDB Cloud Serverless DDL backfills can take 25-60 minutes. The application doesn't detect or retry failed index creation.

### Recommended Fixes

1. **Add post-migration index verification** in `store/migrator.go`
   - After running LATEST.sql, query `SHOW INDEXES` for each expected unique index
   - Log warnings for missing indexes (don't fail startup — just warn)
   - Optionally attempt `CREATE INDEX IF NOT EXISTS` for missing indexes

2. **Make DDL execution resumable**
   - Track which DDL statements succeeded in a `migration_progress` table
   - On restart, skip completed DDL and retry failed ones
   - This prevents partial schema states

3. **Add startup health check for vector DB**
   - In `service.go` initialization, after `NewVectorDB()` returns, call `Validate(ctx)` on the vector DB
   - Log explicit errors if vector DB is unreachable or misconfigured
   - Currently `NewVectorDB` catches connection errors but falls back to `NoOpVectorDB` silently

4. **Document CRDB Cloud Basic limitations**
   - Add to `AGENTS.md`: DDL backfills on CRDB Cloud Basic take 25-60 min
   - Recommend using CRDB Cloud Standard for production (faster DDL)
   - Add to deploy docs: first boot migration may take up to 60 min

5. **Implement the 4-phase LanceDB build enforcement plan** (from previous session)
   - Phase 1: `build_tags_guard.go` — compile-time check
   - Phase 2: `CGO_ENABLED=0` in `Dockerfile.cockroach.fly`
   - Phase 3: `verify:cockroach-pure` Taskfile target
   - Phase 4: Documentation updates
