## Key Finding: Per-Statement Approach FAILS

**All 94 per-statement executions failed** with errors like:
```
ERROR: relation "memo" does not exist (SQLSTATE 42P01)
CREATE INDEX IF NOT EXISTS idx_memo_tenant ON memo(tenant_id);
```

**Root Cause:** The LATEST.sql statements have strict dependency ordering:
1. Tables must exist before indexes can be created on them
2. Foreign key references require referenced tables to exist
3. `IF NOT EXISTS` doesn't help when the referenced table doesn't exist yet

The oneshot approach works because it runs in a **single transaction** where:
- All statements see each other's effects
- Dependencies resolve within the transaction
- Foreign key checks are deferred until commit

## Decision: KEEP ONE-SHOT EXECUTION

**The one-shot `ExecContext` is NOT the bottleneck.** It completes the full 94-statement migration in ~30 seconds locally with 100% success.

**The Cloud Serverless slowness** (~5.5 min for 42/57 tables) is due to:
1. **Serverless Basic tier limitations** (throttling, shared resources)
2. **Distributed DDL coordination** across nodes
3. **Network latency** in multi-region cluster
4. **Schema change GC jobs** (visible in `SHOW JOBS` as "waiting for MVCC GC")
